# desktop

## Overview

The Electron shell that ships Murmur for macOS, Windows and Linux. The main process starts Murmur's own server (`../server/app.ts`) on a loopback port and opens one sandboxed, context-isolated window onto it at `http://127.0.0.1:<port>/`. Because that address is a secure context, notifications, the clipboard and the microphone work as they do on the web. The user picks a Hermes inside the app; there is no built-in Hermes. See [docs/DESKTOP.md](../docs/DESKTOP.md).

## Interface

- `main.ts`: the Electron main process, bundled to `desktop/app/main.js`. It has no exports.
  - Starts the server with `startServer({ host: '127.0.0.1', dataDir: userData, staticDir: <app>/web, env: {}, requireHeader })`. It reuses the last saved port when that port is free.
  - IPC channels (all except `murmur:fullscreen?` are accepted only from the app's own main frame):
    - `murmur:badge`: dock or taskbar badge count, 0 to 9999. On Windows it shows a red overlay dot instead.
    - `murmur:focus`: brings the window to the front.
    - `murmur:theme`: `'system' | 'light' | 'dark'`, sets `nativeTheme.themeSource`.
    - `murmur:fullscreen?`: synchronous query for the current full-screen state.
  - Main to renderer: `murmur:fullscreen` (boolean).
  - Environment:
    - `MURMUR_USER_DATA`: overrides the userData directory.
    - `MURMUR_SMOKE=1`: render the first screen, print `murmur-smoke-ok`, exit.
    - `MURMUR_DEVTOOLS=1`: allows DevTools in packaged builds.
    - `MURMUR_DEV_URL`, `MURMUR_DEV_SERVER_PORT`: development only, set by `scripts/dev.ts`.
- `preload.ts`: the only bridge to the page. It exposes a frozen `window.murmurDesktop = { platform, version, setBadge(count), focus(), setTheme(mode) }`. It also sets `<html data-desktop="mac|win|linux">` before first paint and `data-fullscreen` while the window is full screen. The page's side of the bridge is `src/lib/desktop.ts`.
- `menu.ts`
  - `setMenu(updates?: Updates)`: the application menu. It includes the update items, and Reload and DevTools only in development.
  - `contextMenu(window, params)`: the right-click menu (spelling, Look Up, links, images, clipboard).
  - `type Updates = { check?, ready?, restart? }`
- `state.ts`: `readState()`, `saveState(patch)` and `type Bounds`. The state lives in `userData/desktop.json` and holds `{ port, window, theme }`.
- `updates.ts`
  - `updatesEnabled()`: true only when `__MURMUR_UPDATES__` is set and the app is packaged. On Linux it also needs `APPIMAGE`.
  - `startUpdates()`: electron-updater from GitHub Releases. It checks 15 s after launch and every 4 hours, downloads automatically and installs on quit.
- `env.d.ts`: build-time constants `__MURMUR_VERSION__` and `__MURMUR_UPDATES__`, replaced by esbuild.
- Subdirectories:
  - [scripts](./scripts/README.md): build, dev, dist, icon and smoke-test scripts.
  - `resources/`: icons (`icon.icns`, `icon.ico`, `icon.png`, `icons/`) and `entitlements.mac.plist`. They are generated by `scripts/icons.ts` and committed. This folder has no code.

## Invariants

- The page runs with `sandbox`, `contextIsolation` and `webSecurity` on and `nodeIntegration` off. `preload.ts` is its only access to the app, and the bridge object is frozen.
- The server is started with `env: {}`. Shell variables such as `HERMES_URL` or `MURMUR_PASSWORD` must not leak into the desktop app.
- Every request to the server must carry the `x-murmur-desktop` header. The value is random on each launch. The header is added only for the app's own main frame and same-origin frames, never for opaque-origin agent previews, so other local processes cannot use the loopback port. It is a header, not a cookie, because cookies ignore the port.
- The window never leaves its origin. Other `http`, `https` and `mailto` URLs open in the system browser. `/hermes/api/*` window-opens become downloads. Webviews are blocked, and subframes may only load the app's own origin or `about:`, `data:` and `blob:` URLs.
- Permissions are granted only to the app's own origin, and only these: notifications, microphone-only media, clipboard read and sanitized write, fullscreen.
- Responses get an added CSP of `object-src 'none'; base-uri 'self'; frame-ancestors 'none'`. Scripts are left open so sandboxed agent previews can run.
- The server port is kept between launches because local storage is keyed by origin, port included. A dev server port failure is fatal; otherwise the app falls back to port 0.
- Single instance: a second launch focuses the existing window. On macOS, closing the window hides it and the app keeps running until it really quits.
- Development uses a separate "Murmur Dev" userData directory. Packaged builds use the standard one.

## Side Effects

- Runs the Murmur server in-process on `127.0.0.1`. It writes `userData/murmur.json` and `userData/telegram.json` (see [server](../server/README.md)).
- Writes `userData/desktop.json`: window bounds (debounced by 400 ms), theme and port.
- Release builds make network calls to GitHub Releases for updates and install them on quit.
- Opens external URLs in the OS browser, sets the dock or taskbar badge, and shows native dialogs.

## Verification

- Run: `npm run typecheck` (`tsconfig.desktop.json`) and `npm test`
- Develop: `npm run desktop:dev`
- Smoke test a packaged build: `MURMUR_SMOKE=1 MURMUR_USER_DATA="$(mktemp -d)" <executable>`, or `node desktop/scripts/smoke.ts <executable> [shot.png]`
